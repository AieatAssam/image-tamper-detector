## LICENSING — read before touching any reference implementation

IPOL (Image Processing On Line) publishes peer-reviewed forensics algorithms
WITH reference source. I checked the license on each candidate:

| IPOL article | algorithm | license | what you may do |
|---|---|---|---|
| 2024/462 | **Noisesniffer** | **Apache-2.0** | **adapt the code directly**, with attribution |
| 2022/399 | Reliable JPEG Quantization Table Estimator | AGPL-3.0-or-later | reimplement from the paper only |
| 2021/390 | ZERO: local JPEG grid origin detector | AGPL-3.0-or-later | reimplement from the paper only |
| 2021/355 | Bammey, mosaic analysis / intermediate values | AGPL-3.0-or-later | reimplement from the paper only |
| 2018/213 | Ehret, internal copy-move | GPL-3.0-or-later | reimplement from the paper only |

**This repository is MIT.** Copying, vendoring or deriving from AGPL/GPL source
would make the whole project copyleft. That is the same failure mode that ruled
out TruFor in decision D6.

The distinction, which is standard and not a loophole: **an algorithm described
in a published paper is not itself copyrightable; a specific source file is.**
You may read the paper, understand the method, and write an independent
implementation. You may NOT copy their code, translate it line-by-line, or keep
it in the tree "for reference".

Rule for this round:
- Noisesniffer (Apache-2.0): adapting the code is fine. Record the attribution
  and the license in the module docstring and in docs/.
- Everything else: implement from the PAPER. Do not download the AGPL/GPL
  tarballs into the repo. Cite the paper in the module docstring.
- If you are unsure whether something is a reimplementation or a derivation,
  treat it as a derivation and stop. Report BLOCKED rather than guessing.

## L1 — `prnu` / noise -> Noisesniffer (Apache-2.0, adapt directly)

IPOL 2024/462, "Image Forgery Detection Based on Noise Inspection: Analysis and
Refinement of the Noisesniffer Method".
Source: https://www.ipol.im/pub/art/2024/462/ (462-main.zip, Apache-2.0)

The method estimates a per-image background stochastic noise model and detects
local deviations from it, scoring each detection by its **number of false
alarms (NFA)** — an a-contrario framework, so the output is a statistical
significance rather than an arbitrary score. The refined version adds region
growing to localise deviations.

This is a principled replacement for the current `prnu.py`, which computes the
mean local variance of a denoising residual and thresholds it at a number fitted
to two images. An NFA is exactly the kind of output `to_probability()` should
consume.

Dependencies: numpy, scipy, cv2, skimage (all pinned already) plus **mpmath**
(small, pure Python). Add mpmath only if the implementation genuinely needs it;
resolve its version with the PyPI command in versions.lock.yaml, do not guess.

## L2 — `cfa` never runs -> Bammey mosaic analysis (reimplement from paper)

IPOL 2021/355, Quentin Bammey, "Image Forgeries Detection through Mosaic
Analysis: the Intermediate Values Algorithm". AGPL source — paper only.

The current `cfa.py` requires `strict` unresized evidence and reports
NOT_APPLICABLE everywhere, so it has never contributed. The intermediate-values
approach detects demosaicing structure more robustly than the variance-ratio
method currently implemented, and Bammey's related work is specifically designed
to survive moderate post-processing.

Also relevant: the IMD2020 images are real-life photographs from the internet,
many of them camera originals. Check whether `cfa` now has applicable rows
against that corpus before assuming it is still inert — the strict gate may
already be satisfiable there.

## L3 — `qtable` at 0.388 -> proper quantization-table estimation

IPOL 2022/399, "A Reliable JPEG Quantization Table Estimator". AGPL — paper only.

Two separate problems, diagnose both:

1. **The statistic is constant on the synthetic corpus** — round 2 established
   the generator emits one libjpeg table, so there is nothing to discriminate.
   IMD2020 is real-life imagery with many encoders, so qtable may become
   measurable for the first time. Re-measure there before concluding anything.
2. **AUC 0.388 is below chance**, which is not "no signal" — it is inverted
   signal. Check `higher_is_worse` against the catalog's `signal_direction`, the
   same defect class as round 1's `double_jpeg`.

The estimator paper matters because the current implementation reads the DQT
marker directly, which fails on re-encoded or stripped files; estimating the
table from the coefficients themselves works where the marker is gone.

## L4 — NEW DETECTOR: ZERO, JPEG grid origin (reimplement from paper)

IPOL 2021/390, Nikoukhah, Anger, Grompone von Gioi et al., "ZERO: a Local JPEG
Grid Origin Detector Based on the Number of DCT Zeros and its Applications in
Image Forensics". AGPL source — paper only.

Counts DCT zeros per candidate 8x8 grid origin and detects, a-contrario, regions
whose JPEG grid origin differs from the image's dominant one. A spliced region
pasted from another JPEG almost always lands on a different grid phase, so this
directly targets the `splice` family that `ela` handles badly.

Strong candidate to REPLACE `ela` rather than sit beside it. It produces both a
global score and a localisation map, so it feeds the visualisation work too.

## L5 — `ela` at 0.454 and `entropy` at 0.420: consider retirement

Both are below chance on two independent corpora now.

- `ela` is a 2008 heuristic that this project already demonstrated is meaningless
  on non-JPEG input, where the analyzer re-encodes and manufactures an error
  level reflecting nothing. If L4 lands, ELA's role is covered better.
- `entropy` traces to a single blog post with no peer review, and has been below
  chance every time it has been honestly measured.

Deleting a detector is a legitimate outcome and the plan's ladder favours it.
Do NOT delete either one in this round without first: measuring it on IMD2020,
checking for an inverted `higher_is_worse`, and reporting the numbers. If a
sign flip rescues it, keep it. If it is genuinely uninformative, propose removal
with the evidence and let the next round act on it.

## L6 — `spectral` at 0.536 and `exif` at 0.449

- `spectral`: the catalog cites Durall et al. (CVPR 2020) and Zhang et al.
  (WIFS 2019). Verify the implementation actually does the azimuthal-average
  subtraction and the JPEG-grid frequency exclusion the catalog specifies —
  round 3 established the grid exclusion matters enormously.
- `exif`: EX1 (embedded-thumbnail mismatch) is described in the catalog as the
  strongest EXIF check, and it has never been exercised because the synthetic
  corpus strips EXIF. IMD2020 real-life images should carry EXIF and thumbnails.
  Measure EX1 there before changing any code — this detector may simply have
  never been tested rather than being broken.

## VISUALISATION — L7

The current UI shows one heatmap at a time with an opacity slider. That is a
thin use of what the backend now produces, and the score display predates the
uncertainty work.

Load the `dataviz` skill before writing any chart code, and follow its procedure
(form -> color job -> RUN the validator -> marks -> hover -> a11y -> look at it).
Non-negotiables that apply directly here:

1. **Detector scores are magnitude WITH uncertainty.** We now compute a
   Hanley-McNeil standard error per detector. The right form is a dot plot with
   error bars, ordered by score, with the decision threshold drawn as a
   reference line — NOT a bar chart, and never a bare number implying precision
   the data does not have. A detector at 0.54 +/- 0.03 and one at 0.54 +/- 0.09
   are different claims and must not look identical.
2. **The heatmap ramp must be sequential single-hue, light to dark.** Never a
   rainbow. The current red blanket tint destroys the underlying image; prefer a
   contour or an edge-highlighted mask over a flat wash so the user can still
   see what was manipulated.
3. **Status colors are reserved** for the verdict (authentic / inconclusive /
   manipulated) and must never double as detector-series colors. Verdict must
   carry an icon and a label, never color alone — and `inconclusive` must look
   categorically different from both ends, not like a midpoint.
4. **Run `scripts/validate_palette.js`** on any categorical palette before
   shipping. Do not reason about contrast by eye.
5. **Compare, don't just overlay.** A swipe divider between original and map,
   synced zoom/pan, and the ability to switch detector maps without losing
   viewport position is worth more than a finer opacity slider.
6. **A table view must exist** alongside any chart, and dark mode is a designed
   pass over the same ramps, not an automatic inversion.
7. Keep the honesty work from S11: NOT_APPLICABLE stays visibly distinct from
   clean, and the "evidence, not proof" framing stays.

## MEASUREMENT DISCIPLINE — applies to every item above

The corpus is now good enough that these numbers mean something. That cuts both
ways.

- Re-measure each weak detector on IMD2020 BEFORE changing its code. Several may
  be untested rather than broken — `exif` and `qtable` especially, since the
  synthetic corpus could not exercise them.
- Report within-source AUC with its standard error, before and after, for every
  detector you touch.
- Do NOT tune to raise the fused AUC. Six rounds have established this system's
  honest performance; a sudden jump is the thing to distrust.
- A detector that gets worse after a principled reimplementation is a real
  result. Report it.
