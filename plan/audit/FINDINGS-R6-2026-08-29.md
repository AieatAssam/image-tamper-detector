# Round 6 — recalibration resources

The corpus is no longer the blocker it was: all three real axes are met
(12 strict cameras, 12 AI, 2 signed C2PA) and the source-balance rule holds.
What remains is SCALE. 126 rows cannot separate 12 detectors — every held-out
AUC here carries a standard error near +/-0.08, so most of the current ranking
is noise, including the 0.7333 "best single detector".

I searched for corpora that an agent can actually fetch. Findings below; every
URL was probed on 2026-08-29 and the HTTP status recorded.

---

## K0 — PLAN AMENDMENT: decision D7 was too broad

`plan/plan.yaml` D7 says external corpora are Tier B only, on the grounds that
they are auth-walled. That reasoning is correct for CASIA v2 (Kaggle login) and
COVERAGE (interactive OneDrive), but it is NOT true of IMD2020, which serves
direct HTTP with no authentication.

D7's real principle is "a stage an agent cannot execute offline is guesswork" —
so the test should be EXECUTABILITY, not the word "external". Amend D7 to:
external corpora are Tier B **when acquisition requires authentication or an
interactive step**; a corpus that a script can fetch and checksum unattended may
be Tier A, subject to the licensing rule in K3.

## K1 — PRIMARY RESOURCE — IMD2020 (direct HTTP, no auth, ground-truth masks)

Base URL: `https://staff.utia.cas.cz/novozada/db/`
Probed 2026-08-29, all HTTP 200.

| file | size | contents |
|---|---:|---|
| `IMD2020.zip` | 565 MB | **2,010 real-life manipulated images**, each with a manually created binary mask AND its corresponding real version |
| `IMD2020_real_01.zip` .. `_04.zip` | ~1.9 GB each | **35,000 real images from 2,322 camera models** |
| `IMD2020_prnu_01.zip` .. `_04.zip` | ~1.1 GB each | PRNU-oriented set |
| `IMD2020_Generative_Image_Inpainting_yu2018_01..07.zip` | ~1.6 GB each | generative inpainting manipulations |
| `IMD2020_Generative_Image_Inpainting_yu2018_mask.zip` | 120 MB | masks for the above |

Why this one matters more than its size suggests: **each manipulated image ships
with its own real counterpart.** That satisfies the `source_balance_rule`
natively — the same source contributes both classes — which is the exact
property whose absence caused the round-3 source-identity confound.

`IMD2020_real_01.zip` alone would take the real_camera axis from 12 images to
thousands across 2,322 camera models, which is what `cfa`, `prnu` and `spectral`
have never had.

Citation (requested by the authors, no explicit license — see K3):
Novozamsky, Mahdian, Saic, "IMD2020: A Large-Scale Annotated Dataset Tailored
for Detecting Manipulated Images", IEEE WACV Workshops 2020.

## K2 — SECONDARY — verify before use

- **`marco-willi/synthbuster-plus`** on Hugging Face. Parquet, ~10K-100K rows,
  fetchable via `huggingface_hub` without auth. Synthbuster is a recognised
  benchmark for detecting AI-generated images across many generators.
  **Its HF card declares NO license.** Do not use it until you have read the
  dataset README and established terms. If none can be established, skip it and
  say so — IMD2020's generative-inpainting split already covers synthetic
  manipulation.
- **Wikimedia Commons** — already working, keep it for targeted top-ups.

## K3 — LICENSING RULE (this one is not optional)

IMD2020 publishes no explicit license and its manipulated images were, by the
authors' own description, "downloaded from the Internet". Redistribution is
therefore legally unclear.

Rule, which matches what this repo already does for `data/corpus/real/`:
- Download to a **gitignored** directory. Verify `.gitignore` covers it BEFORE
  the first fetch, not after.
- **Never commit image bytes.** Commit only the manifest: URL, sha256, size,
  split, label, mask path, and the citation.
- Record the citation in `docs/corpus.md` and in the README's data section.
- If a source's terms cannot be established, do not use it. Four rounds of
  refusing to fabricate corpus entries applies here too: unclear provenance is
  its own kind of made-up data.

## K4 — SAMPLING AND COST (read before downloading anything)

Do not naively ingest 2,010 images and re-benchmark. Current per-image cost is
roughly 2.4 s across 12 detectors, so 2,010 images is about 80 minutes per
benchmark run, and calibration runs it repeatedly.

Required approach:
- Start with `IMD2020.zip` (565 MB) ONLY. Do not download the ~1.9 GB real
  shards until the small path works end to end.
- Draw a **fixed-seed stratified sample** — target 300-500 images total,
  balanced across manipulation type and preserving each manipulated image's real
  counterpart so source balance holds. Record the sampled ids in the manifest so
  the selection is reproducible without re-downloading.
- Keep the existing synthetic corpus. It is deterministic, offline and CI-safe.
  IMD2020 becomes an ADDITIONAL corpus axis, not a replacement — CI must keep
  running on synthetic only.
- Report per-image mean duration so the cost of any future expansion is known.

## K5 — WHAT SUCCESS LOOKS LIKE, AND WHAT IT DOES NOT

Expected: with several hundred genuinely independent sources, the standard error
on each AUC drops from roughly +/-0.08 to roughly +/-0.03, and the detector
ranking becomes something that can be trusted rather than noise.

**Do not tune anything to make the fused AUC rise.** The honest reading after
five rounds is that this ensemble is weak. A larger corpus may well make it look
WORSE, because the synthetic corpus's manipulations are cleaner and more uniform
than real-world ones. That outcome is a legitimate and useful result — it would
mean the detectors do not generalise, which is exactly what a bigger corpus
exists to find out. Report whichever way it goes, plainly.

Recalibrate on the enlarged corpus, keep the Hanley-McNeil guard and the
Spearman weight-vs-skill gate, and report before/after for both.
