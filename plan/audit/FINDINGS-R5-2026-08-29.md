# Round 5 — restore the true-negative path

Round 4's copy_move diagnosis was correct and rigorous: instrumentation proved
both pasted regions of `landscape_copy_paste.jpg` contain **zero SIFT
keypoints**, so the detector genuinely cannot see that forgery, and no parameter
was loosened to hide it. Reporting NOT_APPLICABLE rather than a false "clean"
follows the plan's three-valued rule.

The fix was applied too broadly, and that is what this round corrects.

---

## J1 — HIGH — `copy_move` can no longer produce a TRUE NEGATIVE

`copy_move` now returns NOT_APPLICABLE for **every** image where no verified
affine cluster is found. Measured over the synthetic corpus:

| family | not_applicable | applicable |
|---|---:|---:|
| authentic_recompress | 30 | 2 |
| splice | 14 | 0 |
| resize_then_save | 8 | 0 |
| double_compress_aligned | 9 | 1 |
| double_compress_shifted | 9 | 1 |
| local_retouch | 8 | 4 |
| copy_move | 3 | 11 |

The detector is now structurally incapable of saying "I looked and found
nothing". Two consequences:

1. **Its AUC is computed only on images where it already found something**,
   which biases the estimate upward and makes it incomparable with every other
   detector's AUC.
2. **It can never contribute negative evidence to fusion.** A clean image gets
   no reassurance from the one detector that examined it for copy-move forgery.

The distinction the code currently collapses:

- *no keypoints in any candidate region* -> genuinely cannot assess ->
  NOT_APPLICABLE, score None. This is the `landscape_copy_paste.jpg` case and
  round 4 was right about it.
- *sufficient keypoints present, no matching cluster found* -> a REAL NEGATIVE
  -> APPLICABLE, low score, flagged False.

Round 4's own instrumentation already computes everything needed to separate
these: keypoint count after downscale, surviving matches after the ratio test
and the min_offset filter, cluster sizes, RANSAC inliers. Use those.

Proposed rule, but verify it against the corpus before adopting it:
  keypoints < MIN_KEYPOINTS (100)                       -> NOT_APPLICABLE
  keypoints >= MIN_KEYPOINTS but < MIN_MATCHES surviving
    the ratio + min_offset filters                      -> NOT_APPLICABLE
  enough surviving matches, no cluster passing RANSAC   -> APPLICABLE, low score
  >= 1 verified cluster                                 -> APPLICABLE, high score

`landscape_copy_paste.jpg` must STAY not_applicable — round 4 measured 542
keypoints overall but zero inside the pasted regions, and 64 matches surviving
min_offset with a largest cluster of 2. Decide which measured quantity actually
separates that image from a genuine clean landscape, and say which you chose and
why. If the global keypoint count cannot distinguish them, the discriminator has
to be region-local; do not force it with a threshold tuned to one file.

Expected outcome: `authentic_recompress`, `splice` and `resize_then_save` rows
mostly become APPLICABLE with low scores, giving the detector a true-negative
population for the first time.
